# Release statement

Released in this repository under the MIT licence:

- The C++ CBF core and its CMake build (`safety-filter/`), with unit tests
  (`tests/test_cbf_core_cpp.cpp`) run in CI.
- The Zeno guard, schema validator, intent generator, RAN simulator and Docker topology
  of the conference version.
- The campaign script `evaluation/statistical_analysis.py`, with all parameters as
  constants and seeds fixed to run_id * 1000 + 42.
- Per-run results `evaluation/results/per_run.csv` and the decision breakdown
  `evaluation/results/campaign_breakdown.md`, generated by `evaluation/campaign_details.py`.
- The stored report `evaluation/statistical_report.txt` (regenerated in v1.2).
- Ablation, V_max sweep and summary numbers (`evaluation/results/`) and the script that
  makes them and the figures (`evaluation/paper_figures.py`; figures are written to
  `evaluation/figures/`, which is not tracked).
- Latency measurements: `evaluation/results/cpp_eval_us.csv` (`tests/bench_cbf_core.cpp`)
  and `evaluation/results/python_gate_latency.csv` (`evaluation/bench_python_gates.py`).

Not released, and why:

- Per-intent logs. The campaign is deterministic, so they can be regenerated exactly from
  the scripts above.
- Latency values per run. They depend on the machine and include a random term, so they
  are not reproducible in the strict sense (see `LIMITATIONS.md`, item 6).
- LLM prompts or outputs. No language model is used in the campaign.
